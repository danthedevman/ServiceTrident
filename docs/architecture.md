# Architecture and maintenance

ServiceTrident is one product with separate web, API, scheduling, and worker processes. Keep the separation functional; a new folder should own a clear responsibility rather than wrap a single call unnecessarily.

## Request flow

1. Express applies security headers, request limits, origin/content checks, and authentication in `api/src/app.js`.
2. Role gates protect the route groups. Feature routes scope database access to the authenticated workspace. Public status and marketing submissions have explicit, limited routes.
3. Routes validate input and delegate shared business rules or persistence to domain/repository modules.
4. Serializers allowlist client-visible fields. Do not return raw credential documents.

Register public endpoints before authentication and workspace endpoints afterward. Keep the end-user incident-portal restrictions before ordinary feature routes. Do not move a route across these boundaries during refactoring.

## Frontend conventions

`main.jsx` only mounts the app. `application.jsx` owns providers and route registration. Feature modules own their forms, tables, and detail views. Shared components own layout and accessibility.

Use `useResource` for reads and `writeApi`/`useSave` for mutations. Session changes cancel and remove private cached data. Never persist private records in local storage. Only theme/layout preferences belong in local storage. Bounded record navigation links and title/type labels may use account/role-scoped session storage; never persist payloads, credentials, or drafts. Restore inactive record tabs lazily and clear them on sign-out. Preserve drafts during polling, keep loading feedback local, and use section-local skeletons for initial loads without replacing cached content or adding page fades.

Use DataTable for all tables, including exports. A remote table supplies `remote.filtersActive` so the closed filter button can indicate an active filter. Filter UI belongs in `filters` and opens in the shared anchored `TableFilterPanel` without an overlay; navigation tabs belong in `toolbar`. Compact Rows is an account preference. Every list offers a record route; `/api/table-records/:kind/:id` reuses source authorization and safe projections for history/log details. Hiding controls must not clear filters or change exported rows.

Forms use dedicated routes except the explicit on-call quick-add dialog. Use the shared Modal and RecordWorkspace rather than inventing new navigation offsets. Use explicit render conditions and omit empty parent wrappers instead of hiding conditional sections with CSS. Use `ValidatedForm` for custom required/email rules, associated errors, and first-invalid-field focus. Built-in form fields and options retain their immutable IDs/meanings; all System Fields permit admin-controlled labels, Help Text, Required flags, and order while System Field archival is prohibited, and incident resolve/reopen transitions require confirmation; custom additions map to canonical reporting values.

## Jobs and integrations

The scheduler dispatches due monitors independently from check workers. Claims use MongoDB server time and enforce at least one minute between starts. Fixed job IDs reduce duplicate dispatches. Check results are stored in events; in-flight checks cannot overwrite a monitor after its request configuration changes.

Background notifications and monitor checks run in workers. Shared bounded, public-address-pinned transports also support admin-triggered read-only ServiceNow connection tests and OpenID Connect discovery/token/signature verification in the API. These routes enforce authentication, workspace ownership, role checks, time/size limits, and safe errors; do not turn them into arbitrary network proxies. Monitors check public HTTP/HTTPS endpoints using HEAD or GET. Monitor Authentication supports Basic, Bearer, and OAuth client credentials through shared bounded validation. Admin-only writes persist allowlisted public configuration and an encrypted credential envelope using the shared integration key; serializers never return the envelope or secrets. Retaining credentials requires the same target origin and account identity. Workers acquire OAuth tokens through the public-network provider transport, cache them only in bounded memory, and send authorization only to HTTPS without redirects. Authenticated checks require 2xx and omit response headers and bodies; credential revisions guard last-check updates against stale in-flight work. Browser SSO and MFA are outside this HTTP-check model. Extend the shared provider catalog, shared validation, API configuration, worker adapter, UI form, and tests together when adding a provider.

Notification reconciliation writes durable delivery records. The delivery worker performs network I/O separately with retries and sanitized errors. Never store raw provider exceptions, passwords, or connection strings in event history. Demo tags always exclude a record from outbound processing.

## Module boundaries

- `shared/validation` and `shared/forms` are small, reusable rules.
- `shared/integrations/secrets.js` and persistence modules are Node-only; do not import them in browser code.
- API repositories coordinate common persistence, including optimistic-concurrency updates.
- Marketing templates contain only application-authored HTML. Runtime configuration is escaped. Contact data is rendered as text in the React inbox.

Every nontrivial exported function should have JSDoc describing its responsibility and relevant input/output or safety boundary. Prefer explicit code over generic service frameworks. Run lint, formatting, build, unit tests, and the affected integration tests after moving modules.

## Storage and table reads

`shared/persistence/database.js` selects MongoDB or PostgreSQL. The MongoDB implementation uses the native driver; PostgreSQL implements the bounded document-repository contract in separate query, cursor, codec, update, migration, and connection modules. See `docs/database-backends.md` for deployment and schema tradeoffs. Do not add persistence operators without parity tests.

Every DataTable now uses an explicit server source or an existing remote endpoint. The browser holds page/query state, not a complete dataset for filtering. `/api/tables/:kind` owns its source and column allowlists and reuses the same authorization and filters for CSV export. Growing record collections use database queries; bounded embedded configuration is filtered on the API. `/api/references/:type` returns at most 30 matches plus separately authorized selected labels. The table/reference route modules enforce their own role restrictions immediately after authentication.

## Documentation and visual verification

Deliver behavior changes with README, bundled Help, and affected deployment/maintenance documentation. Keep current defaults, exact labels, permission rules, and limitations consistent across guides. Follow the documentation process in [AGENTS.md](../AGENTS.md) and [Help screenshot capture](help-screenshots.md). Screenshots use isolated synthetic fixtures; never live records, credentials, or post-capture redaction. Rebuild affected local services and bundle updated Help images before completion.

Event detail resolves triggering incidents within the authenticated workspace using an exact same-element match on saved monitor ID and check timestamp. The response projects only incident ID, title, and status and caps results at 100 with an explicit truncation flag. PostgreSQL compiles the shared `$elemMatch` query into parameterized JSON array matching.

Task-board native dragging uses a scoped animation loop to scroll the horizontal lane owner and vertical board-page owner near their visible edges. Drop, drag end, pointer exit, and unmount stop scrolling; saved ordering and authorization continue through the existing revision-checked task/lane writes.

Monitor Check Now is an admin-only, workspace-scoped audited POST action. A database-time atomic update coalesces pending requests, applies a one-minute request cooldown, and schedules the earliest start preserving minimum check spacing. Dispatcher and worker claims permit a pending one-off check on paused monitors, clear the pending flag atomically, and retain the pause setting. Events list association enrichment streams batches of 100 events and queries exact saved trigger pairs once per batch; only incident ID, title, and status reach clients. CSV exports use the same batching.

Record numbering uses atomic per-workspace/type counters and stable identity mappings on both backends. New records get server-owned numbers before insertion; existing records initialize them on access, preserving internal IDs and existing content/revisions. Embedded catalog and settings records use the same identity mapping. Counters and identities must be included in backups; do not reset them. Incident event filtering uses workspace ownership plus exact saved monitor/timestamp pairs before counting, sorting, paging, and CSV export. Browser-style user agents are randomly selected once per check from 73 presets and retained across redirects; this is not browser automation or a bot-protection bypass.

## AI Chat and Confirmed Actions

`/api/ai/chat` plans requests with a fixed vocabulary, performs tenant-scoped bounded reads with an explicit projection, and generates a cited answer. Model output never becomes raw queries, URLs, or commands. Published knowledge retrieval excludes drafts. Chat actions are allowlisted, role checked, and encrypted into ten-minute proposals bound to the actor, workspace and effective role. `/api/ai/actions` requires confirmation, rechecks availability and permissions, records a durable unique replay receipt in `contactTokens`, and calls the same incident/task/article save handlers as normal writes. Receipt expiry uses the existing TTL index. Validation failures consume a proposal; ask again after correcting the record. Audit metadata includes the target and operation but excludes prompts, output and action tokens.

Demo availability is derived from an active `demoData` batch and `aiDemoEnabled`; fixed narratives never call providers; navigation reads only bounded metadata from the active demo batch. `aiChatEnabled` controls live chat, and the user’s `aiChat` preference gates both modes. Chat remains memory-only, scoped by account/role. Successful actions use shared cache invalidation for immediate refresh in the current browser, preserving mounted form drafts; other users retain normal polling. One live turn charges the persisted daily generation ceiling once but invokes the provider twice.

On-call schedule validation uses UTC half-open intervals and rejects overlapping service scopes, including global coverage. Calendar and list dialogs retain canonical UTC strings until editor initialization; stripping the zone before parsing would shift coverage by the browser timezone. Editors preserve timestamp precision through millisecond handoffs. Conflict errors contain only the bounded conflicting interval and scope guidance, without record contents or identifiers.

Kanban task titles open a lazy, authorized task-detail dialog using the same TaskDetails presentation as full records. The dialog preserves board state and reuses WorkEditor for in-place editing through existing task validators, permissions, revision checks, and audit middleware. Form action contexts point to the modal footer rather than the page header; pending saves block closing, dirty edits require discard confirmation, and Open Record remains available for attachments and the full workspace. The shared Modal owns focus trapping, Escape, focus restoration, and vertically scrolling content. Event response sections use the header table’s own heading rather than a duplicate wrapper heading.

RCAs are internal, workspace-scoped `rcas` records with dedicated read/write routes and a server-defined table source. API validators bound text and reference arrays, reject unknown/actor/ownership fields, verify tenant-owned incident/task relationships, enforce completion rules and CAS revisions, and use the existing API audit middleware. PostgreSQL migration 8 adds the collection-compatible table; shared indexes cover workspace/update time and both reference arrays. Sequential numbering assigns the RCA prefix. End-user and machine access remain denied. RCA archive is retained state, not deletion. RCA Form Builder uses workspace rcaFields configuration, shared bounded custom-value validation and saved field metadata. Archived custom values are retained but hidden. Admin-only schema writes use settings CAS; all record writes enforce required policy. Canonical completion rules remain enforced. AI write tools do not yet manage RCAs.

Automatic service incidents snapshot an initial `alertGroupUntil` from the workspace grouping setting. Reconciliation unions immutable monitor/check-time pairs during that bounded window (maximum 1,000), auditing changes without contents. Incidents and recoveries are visible immediately; outbox insertion waits until the cutoff. Existing legacy incidents retain immediate delivery. Impact notifications use saved triggering check snapshots rather than current healthy monitor state, preserving failure diagnostics through fast recovery. Outbox IDs, leases, and sent-state checks retain existing idempotency. Grouping settings affect new incidents only; 0 preserves immediate delivery.

Incident origin is immutable server metadata: browser creates use manual, machine creates use integration with verified account ID/name, confirmed AI creates use ai, and reconciliation chooses monitor when failing check references exist or automation for service health without those checks. Patches retain the original source. Source filters are validated and indexed by workspace/source/creation time; CSV reuses them. Detail reads resolve at most 20 distinct monitor/check pairs using tenant-scoped metadata projections. Event links obey retention and missing/deleted records remain text. Account links are admin-only; end users receive no internal trigger metadata.

Saved-record exports use shared RecordExportActions in record secondary actions (including task previews and generic log records). Each download performs a fresh ordinary authorized API read with bounded recordExport=csv|pdf metadata; existing tenant, role, retention and safe projections remain authoritative. API auditing records the export request/format and outcome, not downloaded content; PDF generation happens in the browser and its completion is not a server-verified event. Collection-backed records select only the requested saved item after the authorized read. Explicit client field allowlists omit credentials/configuration secrets and monitor URL queries; current form schemas omit archived custom fields. CSV neutralizes formulas. PDF rendering and bundled fonts load only on demand, with no external rendering service or remote image fetches. Exports contain saved record values and article/runbook text, not drafts, attachments, embedded images, comments/work notes or lazy related-list datasets; RCA link titles are included. Session changes/unmount cancel pending work. The PDF renderer is presentation only and never supplies authorization.

Monitor interval presentation supports Minutes and Hours. The shared conversion helper accepts only 1–1,440 whole minutes (with insignificant floating-point tolerance during unit conversion). The browser converts to canonical intervalMinutes before saving; the API and scheduler retain the existing integer-minute contract and bounds. Unit choice is presentation state rather than a saved scheduling option.

### Incident collaboration and in-app notifications

Incident comments store bounded, validated mention snapshots (up to 20 IDs) and an `alertRecipientIds` array of active, authorized recipients calculated from participants, assignee, selected mentions and current watcher-group membership. Public comments also queue the existing per-person SMTP delivery. Work notes never queue email and restrict recipients to responders/admins. Watcher IDs are saved with an incident revision compare-and-swap; groups do not grant access. Group email/Slack channel and user Slack ID are bounded directory configuration, not new outbound delivery adapters.

`GET /api/notifications` uses the workspace/recipient/createdAt index on `incidentComments`, limits the candidate set to 100, batch-loads current incident permissions, and returns reference metadata without message bodies. Note permissions are applied before reading candidates. Notifications therefore inherit comment retention and deletion; they are not a separate content copy. `POST /api/notifications/read` advances only the signed-in user’s seen timestamp, using a bounded past check time. Polling is every 30 seconds. Portal routes explicitly allow only these reads and the mark-read action; machine credentials remain excluded. The bell resolves records through normal record navigation and current API authorization.

The private shell owns a 48-pixel toolbar with record tabs and the notification bell. Main content has one clipped 1-pixel perimeter and 16-pixel corners; its internal route pane owns vertical scrolling, with no document scrollbar gutter. The toolbar and outer frame share the sidenav palette. The info toggle follows primary record actions. Desktop details remain resizable; collapse releases all reserved width. Below 1,200 pixels, details render only as an explicitly opened native modal, with outside-click/Escape/close dismissal and focus restoration, independent of the saved desktop collapse preference.

Demo batches include 50 RCAs with Draft/In Review/Completed statuses, populated findings, and same-batch incident/task links. Generation uses `validateRca`, the current RCA custom-field schema, ordinary record numbering and existing batch-scoped insert/cleanup operations. Existing batches remain immutable until the admin explicitly deletes and re-adds them. RCA demo regression tests verify list/detail/related reads, custom fields, numbers and preservation of unrelated analyses.

Breadcrumbs reuse cached, authorized detail reads for current parent labels. Knowledge articles include their base when assigned; history records retain allowlisted parent kinds and link to declared related sections using the presentation-only `related` query parameter. Unsupported related IDs are ignored; every list/detail API still applies its own role/workspace checks. Knowledge-base cards use the shared infinite-scroll observer against the page scroll owner, fetch bounded 25-row pages and pause after errors until Retry. Help categories use a bounded sticky scroll area on desktop and horizontal navigation on mobile.

Record tab labels refresh after their navigation entry is registered, including records already in the resource cache. Persisted labels are bounded to 512 characters; CSS truncates the single-line visible label while the hover title retains the bounded full label.

New demo batches include six in-app comment/work-note alerts for the seeding administrator. These reuse same-batch incident comments and recipient metadata, are removed with the batch, and never enqueue external delivery. Existing batches require explicit deletion and recreation to receive them.

The shell mounts one set of global action controls. A viewport subscription places Search, Create, and Notifications beside Profile in the mobile navigation and in the application toolbar on desktop. Record tabs retain their own row on mobile; an empty tab row has zero height. Notification menus remain viewport-bounded.
